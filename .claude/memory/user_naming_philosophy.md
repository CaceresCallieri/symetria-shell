description: How the user approaches naming decisions — preferences, values, and collaboration style

---

The user treats naming as one of the most important parts of building software. Names are not labels — they are philosophical commitments that shape how a system is perceived and how it evolves.

Key characteristics:
- Prefers Greek and Latin roots with genuine etymological depth
- Values names that feel "inevitable once discovered" — alignment over excitement
- Thinks in conceptual clusters (Kosmos/Symmetria/Vigilia form a family of states)
- Willing to let names emerge through conversation rather than forcing decisions
- Cares about orthographic intentionality (e.g., Kosmos vs Cosmos — the K signals intent)
- Rejects trendy startup naming, buzzwords, and marketing-first approaches
- Sees naming as concept discovery, not brainstorming
- Open to letting a name expand beyond its original scope if it organically fits (as Symmetria did)
- Appreciates when the agent acts as "Cartographer of Meaning" — mapping conceptual terrain rather than generating options
